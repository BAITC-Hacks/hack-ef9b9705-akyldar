# AI-модуль: вопросы и Task Card

Go-модуль в `ai/`: помогает бизнесу уточнить задачу и получить редактируемую карточку. Подтверждение, сохранение, рейтинг, публикация и предложения команд остаются ответственностью backend. При запуске `backend/cmd/server` этот модуль подключается к общему HTTP-серверу. Для полного запуска проекта см. [../README.md](../README.md); технические детали интеграции — в [integration.md](docs/integration.md).

## Что делает модуль

1. `POST /api/ai/questions` принимает описание и возвращает 3–5 уточняющих вопросов.
2. `POST /api/ai/card` принимает описание и ответы, возвращает карточку со всеми обязательными строковыми полями.
3. Проверяет вход, форму внешнего ответа и отдельные признаки неподтверждённых фактов; ограничивает время, размер данных и число попыток.
4. При недоступности AI возвращает явный резервный режим: `X-AI-Mode: fallback`. Карточка сохраняет исходное описание в `context`; остальные поля заполняет человек.

В тексте задания указано «12 полей», но перечислено 11. Текущая schema содержит ровно эти **11** ключей; двенадцатое поле не добавлено. `score` не возвращается.

## Быстрый запуск без ключа

Установите Go 1.22 или новее и добавьте его в PATH. Команды ниже выполняются в PowerShell из корня клона; после `Set-Location` рабочая папка — `ai/`:

```powershell
Set-Location .\ai
go version
$env:AI_FORCE_FALLBACK = 'true'
$env:AI_TIMEOUT_SECONDS = '15'
$env:AI_MAX_ATTEMPTS = '2'
go run ./cmd/demo
```

Если вы уже в `ai/`, пропустите `Set-Location`. Сервер слушает `http://127.0.0.1:8080`. Другой адрес можно задать через `go run ./cmd/demo -addr 127.0.0.1:8081`.

Клон не содержит `.env`, переносимый Go или `.local/`. Для запуска без ключа дополнительных файлов не нужно. Prompts и schemas встроены в Go binary при сборке; внешних Go dependencies нет.

В отдельном PowerShell выполните два запроса. Передача UTF-8 bytes сохраняет русский и казахский текст и в Windows PowerShell:

```powershell
$baseUrl = 'http://127.0.0.1:8080'
$questionsJSON = @{ description = 'Хотим автоматизировать работу склада' } | ConvertTo-Json
$questionsResponse = Invoke-WebRequest -UseBasicParsing `
  -Uri "$baseUrl/api/ai/questions" -Method Post `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($questionsJSON))
$questionsResponse.Headers['X-AI-Mode']
$questionsResponse.Content

$cardJSON = @{
  description = 'Хотим автоматизировать работу склада'
  answers = @(
    @{ question = 'Кто будет пользоваться решением?'; answer = 'Кладовщики.' }
    @{ question = 'Какие данные доступны?'; answer = 'Учёт остатков ведём в Excel.' }
    @{ question = 'Какой результат нужен?'; answer = 'Веб-приложение для учёта остатков.' }
  )
} | ConvertTo-Json -Depth 5
$cardResponse = Invoke-WebRequest -UseBasicParsing `
  -Uri "$baseUrl/api/ai/card" -Method Post `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($cardJSON))
$cardResponse.Headers['X-AI-Mode']
$cardResponse.Content
```

В forced fallback оба ответа имеют статус 200 и заголовок `fallback`. Card fallback намеренно не структурирует ответы: `context` равен исходному `description`, остальные значения — `""`. Это позволяет продолжить ручное заполнение и не выдаёт резервный алгоритм за работу AI.

## Live-режим и окружение

Шаблон: [.env.example](.env.example). Go-приложение читает переменные **процесса**. Для локального запуска в Windows добавлен [run.ps1](run.ps1): он читает соседний `.env` как данные, передаёт пять разрешённых переменных серверу и восстанавливает прежнее окружение после завершения. Значения `.env` имеют приоритет над переменными текущего терминала; флаг `-ForceFallback` имеет приоритет над файлом. Ключ хранится только в локальном `.env`, исключённом через `.gitignore`.

Для первого live-запуска создайте локальную конфигурацию из корня клона (если `.env` уже есть, сохраните его):

```powershell
if (-not (Test-Path .\ai\.env)) { Copy-Item .\ai\.env.example .\ai\.env }
```

В локальном `ai/.env` задайте свой `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-4.1-mini` и `AI_FORCE_FALLBACK=false`. Ключ не входит в распространяемые файлы. Затем из корня проекта запустите:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ai\run.ps1
```

Из `ai/` укажите `-File .\run.ps1`. Параметр `-ExecutionPolicy Bypass` действует только для запускаемого процесса и не меняет системную политику. Сервер слушает `http://127.0.0.1:8080`; для другого адреса добавьте `-Address 127.0.0.1:8081`, для резервного режима — `-ForceFallback`. Launcher использует установленный Go из PATH; предусмотренный локальный резерв `.local/tools/go/bin/go.exe` в клон не входит. `.env` необязателен, если переменные уже переданы процессу. Файл поддерживает строки `KEY=value`, пустые строки и отдельные комментарии `#`; переменные и команды внутри значений не раскрываются и не исполняются.

При прямом `go run ./cmd/demo` файл `.env` по-прежнему не загружается: передайте переменные через настройки запуска/secret storage backend или окружение процесса. Не помещайте реальный ключ в код, fixture, README или frontend.

| Переменная | Значение и поведение |
|---|---|
| `OPENAI_API_KEY` | Серверный API key; отсутствующий ключ включает fallback |
| `OPENAI_MODEL` | Имя модели; отсутствующее значение включает fallback; рекомендация `gpt-4.1-mini` |
| `AI_TIMEOUT_SECONDS` | Общий лимит одной операции; по умолчанию `15`, допустимо `1`–`60` |
| `AI_MAX_ATTEMPTS` | Общее число обращений к провайдеру; по умолчанию `2`, допустимо `1`–`2` |
| `AI_FORCE_FALLBACK` | По умолчанию `false`; `true` полностью исключает обращения к провайдеру |

После передачи ключа в окружение того PowerShell, где запускается сервер:

```powershell
$env:OPENAI_MODEL = 'gpt-4.1-mini'
$env:AI_FORCE_FALLBACK = 'false'
go run ./cmd/demo
```

После смены env перезапустите процесс. Подписка в интерфейсе ChatGPT сама по себе не подтверждает API-доступ. При разработке изолированного стенда 23.09.2026 два запроса к реальному API прошли: RU questions и KK card вернули `X-AI-Mode: live` на `gpt-4.1-mini`. Это исторический smoke исходного стенда; в новом клоне live-запросы не повторялись. Полная оценка всех 18 semantic cases ещё не выполнена.

Клиент использует OpenAI Responses API и нативный Structured Outputs: `text.format.type = "json_schema"`, `strict = true`. Синтаксис сверён с [официальной документацией](https://developers.openai.com/api/docs/guides/structured-outputs), рекомендуемая модель — со [страницей gpt-4.1-mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). Модель задаётся конфигурацией, бизнес-логика не зависит от её имени.

## Контракты

Все запросы: `Content-Type: application/json`. Все ответы endpoints: JSON, `Cache-Control: no-store`. Успешный ответ содержит `X-AI-Mode: live` или `fallback`; форма JSON body от режима не меняется.

Questions request:

```json
{"description":"Хотим автоматизировать работу склада"}
```

Questions response, пример формы, а не запись live-вызова:

```json
{
  "questions": [
    "Как сейчас организована работа склада?",
    "Кто будет пользоваться решением?",
    "Какие данные доступны для работы?"
  ]
}
```

Card request обязательно содержит оба ключа; допустимо `answers: []`:

```json
{
  "description": "Хотим автоматизировать работу склада",
  "answers": []
}
```

Card response в fallback для этого ввода:

```json
{
  "title": "",
  "context": "Хотим автоматизировать работу склада",
  "need": "",
  "users": "",
  "data": "",
  "constraints": "",
  "expected_result": "",
  "success_criteria": "",
  "contact": "",
  "interaction_format": "",
  "topic": ""
}
```

Схемы: [questions](schemas/questions.schema.json), [card](schemas/card.schema.json). Неизвестные, пропущенные ключи и неподдерживаемые типы отклоняются. В `answers` каждый элемент содержит строковые `question` и `answer`; вопрос непустой, ответ может быть пустой. Контракты, лимиты, статусы и подключение router описаны в [integration.md](docs/integration.md).

## Архитектура и достоверность

```text
HTTP handlers → validation → service → provider → Responses API
                              ↓          ↓
                           fallback   output validation
```

`Config` управляет моделью и лимитами; небольшой `Provider` позволяет подставить fake в тестах. Вход передаётся отдельно от system prompt. Два [prompt](prompts/) определяют разные задачи: найти полезные уточнения и консервативно составить карточку. [Schemas](schemas/) задают структуру; Go повторно строго проверяет её локально.

Допустимые факты берутся только из `description` и пользовательских ответов. Текст `question` помогает понять ответ, но сам не подтверждает факты бизнеса. Пустой ответ и «не знаю» не создают фактов. Явное исправление заменяет предыдущую информацию; неразрешимый конфликт оставляет затронутое поле пустым. Название кратко отражает задачу; `topic` заполняется только при однозначной опоре на текст. Инструкции внутри данных не должны менять системные правила.

Проверки чисел, контактов, URL, handles и некоторых названий технологий снижают риск очевидных добавлений. Это эвристики: они могут отклонить корректное перефразирование и не обнаруживают все смысловые ошибки. JSON Schema проверяет структуру, а не правдивость. Поэтому отдельно предусмотрены [semantic evaluation cases](testdata/evaluation_cases.json) и обязательная ручная проверка карточки перед подтверждением. AI не считает рейтинг и не публикует задачи.

Консервативный guard исключает текст `question` из доказательств. Поэтому на вопрос «Срок — 2 недели?» ответ «Да» может подтвердить смысл для человека и модели, но число `2` не будет найдено в `description`/`answer`: карточка с этим числом уйдёт в manual fallback после исчерпания допустимых попыток. Для однозначного ввода бизнес может ответить «Да, 2 недели». Аналогично перефразирование «две недели» в «2 недели» может быть отклонено: guard не переводит числительные в цифры. Код не считает числа из вопросов автоматически подтверждёнными.

## Проверки

Основные проверки не требуют API key и интернета; provider заменяется fake/локальным `httptest` server:

```powershell
go test -count=1 -cover ./...
go vet ./...
```

Историческая проверка исходного изолированного стенда выполнена 23.09.2026 на Go 1.27.1, `windows/amd64`; переносимый официальный архив проверен по SHA256:

| Проверка | Результат |
|---|---|
| `gofmt -w` для всех `.go` | Выполнено |
| `go test -count=1 -cover ./...` | Exit 0; `hackalem/ai` — 94,4% statements; `cmd/demo` — 0,0% автоматического покрытия |
| `go vet ./...` | Exit 0 |
| `go build -o .local/demo.exe ./cmd/demo` | Exit 0 |
| Отдельный smoke собранного demo | Успешно на `127.0.0.1:18080`; после проверки процесс остановлен |

Тесты выполнялись с `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOSUMDB=off`, `GOCACHE` и `GOMODCACHE` внутри рабочей папки. Ключи и интернет не использовались; `httptest` обращался только к loopback. Нулевое автоматическое покрытие `cmd/demo` отделено от успешного запуска реального собранного процесса.

Smoke подтвердил RU и KK questions: 200, `fallback`, по 5 вопросов; card: 200, `fallback`, ровно 11 строк, `context` сохраняет исходное описание вместе с пробелами, остальные 10 значений пустые. Пустое описание вернуло 400, тело 65 537 bytes — 413, `text/plain` — 415, GET к endpoint — 405.

Тесты с заранее заданными ответами проверяют код, а не качество настоящей модели. Историческая live-проверка подтвердила два запроса через реальные provider/service/handlers: RU questions — 5 вопросов, KK card — валидная карточка с пустыми неизвестными полями; оба HTTP 200/live с одной попыткой. Это базовая проверка подключения, не полная семантическая оценка. Совместный flow backend → AI → catalog → proposal проверяется интеграционным тестом backend; статусы разнесены в [checklist](docs/integration-checklist.md).

Подробный [отчёт проверки](docs/test-results.md) содержит точную среду, выполненные команды, результаты smoke и непроверенные части, включая отдельно не запускавшийся race detector.

Для проверки жюри: запустите forced fallback, выполните два PowerShell-запроса, убедитесь в `X-AI-Mode: fallback`, затем отправьте пустой `description` и убедитесь, что получен 400. Для live-демонстрации нужен отдельный доступ к API; при ошибке сети приложение честно показывает fallback. Последовательный сценарий: [demo.md](docs/demo.md).

## Данные, рейтинг и границы

[Fixtures](testdata/) помечены synthetic: 5 draft descriptions разной полноты, 5 полных карточек с объясняющими их исходными описаниями/ответами, 5 команд, 5 предложений. Темы — logistics, education, retail, healthcare administration, analytics. Идентификаторы хранятся в fixture envelope, не в AI schema. `example.com` — демонстрационные ссылки, не существующие прототипы. Медицинская тема касается только администрирования, без реальных персональных данных.

В интегрированном backend `rating.Calculate`: `context` и `need` дают по 10, `data` — 20, `expected_result` и `success_criteria` — по 15, `constraints` и `users` — по 10, `contact` и `interaction_format` — по 5. Заполненность определяется как `strings.TrimSpace(value) != ""`; буквальное «не знаю» тоже считается заполнением. AI не меняет формулу и не возвращает score; правила и границы интеграции описаны в [integration.md](docs/integration.md).

Fallback-вопросы определяют заполненные категории и язык эвристически; фразы без характерных казахских букв и смешанный текст могут определяться неточно. Если описание полностью исчерпывающее, минимум 3 вопроса может конфликтовать с запретом повторов. Модуль не доказывает наличие пробелов и не скрывает это ограничение.

Сам модуль `ai/` не владеет frontend, сохранением задач, rating, подтверждением, публикацией, каталогом или предложениями; это ответственность интегрированного backend и frontend. Их совместный HTTP flow проверен отдельным тестом: см. [checklist](docs/integration-checklist.md).

## Передача backend-разработчику

- В интегрированном запуске backend вызывает `RegisterRoutes` на общем `http.ServeMux`; standalone `cmd/demo` остаётся удобным способом проверить модуль отдельно.
- Передавать server env и request context; оставить человеческое редактирование и подтверждение.
- Читать `X-AI-Mode`; для другого origin разрешить его чтение через `Access-Control-Expose-Headers`.
- Согласовать двенадцатое поле только если оно действительно требуется и политику «не знаю» в найденной формуле rating.
- Для live-режима отдельно выполнить semantic evaluation; локальный fallback flow уже покрыт [интеграционным checklist](docs/integration-checklist.md).
