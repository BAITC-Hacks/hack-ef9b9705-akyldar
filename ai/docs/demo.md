# Демонстрация AI-модуля: 2–3 минуты

Это сценарий самостоятельной проверки только AI-модуля. Он не заменяет полный сценарий проекта: для демонстрации backend, rating, публикации и предложений используйте [корневой demo-script](../../docs/demo-script.md). HTTP-ответ AI с карточкой сам по себе не означает её сохранение, подтверждение или публикацию.

Все участники, контакты, материалы и примеры ниже синтетические. Адреса `example.com` демонстрационные; ссылки в proposals не являются работающими прототипами. Карточки из `testdata/cards.json` — подготовленные образцы с источниками, а не запись успешных вызовов AI.

## Перед выступлением

Установите Go 1.22+ в PATH. Клон не содержит `.env` и portable Go; для live создайте локальный `.env` из `.env.example` по [README](../README.md). Из каталога `ai` запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1`: Windows launcher загрузит локальный `.env`, если он есть. Для резервного режима добавьте `-ForceFallback`. Параметр execution policy действует только для этого процесса. Адрес по умолчанию — `http://127.0.0.1:8080`; при параллельном backend выберите `-Address 127.0.0.1:8081` и измените `$baseUrl` ниже. При прямом `go run ./cmd/demo` переменные окружения должны попасть в процесс до запуска; `.env.example` сам по себе их не загружает. Не показывайте секретный ключ на экране.

Выберите режим и назовите его перед началом:

- **Live:** действительный вызов провайдера с заголовком `X-AI-Mode: live`. Наличие ключа само по себе не доказывает успешный вызов; проверяйте заголовок каждого ответа.
- **Fallback:** локальная резервная обработка с `X-AI-Mode: fallback`. Если ключа нет или вызов не удался, резервный ответ не выдаётся за результат модели.
- **Ручное заполнение:** человек вводит факты сам. Даже если результат выглядит как полная карточка, это не AI-структуризация и не подтверждение backend.

Live evaluation и полный путь платформы имеют отдельный статус. Этот документ — сценарий и ожидаемые смысловые инварианты, а не отчёт о выполненном live-тесте. Перед защитой прогоните сценарий с текущей конфигурацией и зафиксируйте фактический режим. Если всё начинается в fallback, используйте резервный сценарий ниже.

В live-вызове формулировки вопросов и допустимые перефразирования карточки могут отличаться. Пары ниже — точный заготовленный ввод бизнеса для воспроизводимого API-сценария; они не являются заранее записанным ответом модели. Если реальные вопросы отличаются, ответы вводятся к соответствующим категориям. Не приписывайте модели текст, который она не вернула.

## Точные запросы для PowerShell

Следующий помощник работает с `Invoke-WebRequest` и выводит только режим и JSON ответа. Он не выводит ключ и не требует frontend. Выполняйте в отдельном терминале при запущенном стенде.

```powershell
$baseUrl = 'http://127.0.0.1:8080'

function Invoke-AIDemo {
    param([string]$Path, [object]$Payload)
    $json = $Payload | ConvertTo-Json -Depth 10
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
    $response = Invoke-WebRequest -UseBasicParsing -Method Post `
        -Uri ($baseUrl + $Path) `
        -ContentType 'application/json; charset=utf-8' -Body $bytes
    Write-Host ('X-AI-Mode: ' + $response.Headers['X-AI-Mode'])
    $response.Content | ConvertFrom-Json | ConvertTo-Json -Depth 10
}

$description = 'Хотим автоматизировать работу склада'
$initial = @{ description = $description }
Invoke-AIDemo -Path '/api/ai/questions' -Payload $initial

$partialAnswers = @(
    @{
        question = 'Как сейчас устроена работа и кто будет пользоваться решением?'
        answer = 'Сейчас приёмку и выдачу товаров записываем на бумаге. Нам нужно видеть остатки и движения товаров в одном месте. Пользователи — кладовщик и менеджер склада.'
    },
    @{
        question = 'Какие данные доступны?'
        answer = 'Есть выгрузка остатков товаров в CSV без персональных данных.'
    },
    @{
        question = 'Какой результат вы ожидаете?'
        answer = 'Веб-интерфейс для регистрации приёмки, выдачи и просмотра остатков товаров.'
    }
)
$partial = @{ description = $description; answers = $partialAnswers }
Invoke-AIDemo -Path '/api/ai/card' -Payload $partial

$additionalAnswers = @(
    @{
        question = 'Какие ограничения нужно учесть?'
        answer = 'Решение должно работать в локальной сети склада; срок демонстрации — две недели.'
    },
    @{
        question = 'Как будете проверять результат?'
        answer = 'На 10 синтетических операциях приёмки и выдачи итоговые остатки должны совпасть с ручным расчётом.'
    },
    @{
        question = 'Как с вами связаться?'
        answer = 'warehouse-demo@example.com'
    },
    @{
        question = 'Какой формат взаимодействия удобен?'
        answer = 'Один созвон в неделю и вопросы по электронной почте.'
    }
)
$complete = @{
    description = $description
    answers = @($partialAnswers) + @($additionalAnswers)
}
Invoke-AIDemo -Path '/api/ai/card' -Payload $complete
```

Это демонстрирует добавление фактов человеком и повторную генерацию через API. Полноценное ручное редактирование карточки в интерфейсе **не проверено в AI-поставке**. Для показа принципа откройте ответ как локальный черновик в редакторе и подпишите «ручной черновик, не сохранён». Не изображайте редактирование в IDE как готовую функцию приложения.

В live-результате `complete` ожидаются следующие сведения; точное совпадение формулировок не требуется:

| Поле | Ожидаемый смысл и источник |
|---|---|
| `title` | Учёт или автоматизация склада; краткое название из description и ответов. |
| `context` | Приёмку и выдачу записывают на бумаге; первый ответ. |
| `need` | Видеть остатки и движения товаров в одном месте; первый ответ. |
| `users` | Кладовщик и менеджер склада; первый ответ. |
| `data` | Выгрузка остатков в CSV без персональных данных; второй ответ. |
| `constraints` | Локальная сеть склада, демонстрация через две недели; четвёртый ответ. Бюджет не сообщён. |
| `expected_result` | Веб-интерфейс приёмки, выдачи и просмотра остатков; третий ответ. |
| `success_criteria` | Итоговые остатки совпадают с ручным расчётом на 10 синтетических операциях; пятый ответ. |
| `contact` | `warehouse-demo@example.com`; шестой ответ. |
| `interaction_format` | Один созвон в неделю и вопросы по почте; седьмой ответ. |
| `topic` | Складская логистика, однозначно следует из описания. |

Если реальная модель добавила неподтверждённый факт, отметьте это как дефект семантики, удалите его вручную и не называйте прогон успешным. Валидный JSON сам по себе не доказывает достоверность фактов.

## Рейтинг и подключение платформы

Ни один ответ AI не содержит `score`. Код `rating.Calculate` найден в `origin/backend` (`ba61fef`), но численные баллы и их рост в совместном сценарии **не проверены**. Можно сравнить, какие сведения появились после уточнений, но нельзя выдавать количество заполненных полей за фактически полученный backend-рейтинг.

После подключения backend покажите фактически рассчитанный результат до и после дополнений. В просмотренной формуле `context` и `need` дают по 10, `contact` и `interaction_format` — по 5; прочие веса и уровни перечислены в [integration.md](integration.md). Пустота проверяется только trim: текст «не знаю» тоже получает баллы. Согласуйте это поведение с backend и проверяйте факты вручную; AI-поставка формулу не меняет.

Сохранение, расчёт и пересчёт рейтинга, подтверждение, публикация, каталог, отправка и просмотр proposal, Accept и статус `accepted` пока **не проверены вместе с AI**. Наличие реализации в других ветках не подтверждает их работу в этом стенде. После интеграции пройти [полный checklist](integration-checklist.md). При демонстрации синтетического proposal явно сказать: «Это пример данных для интеграции, он не отправлен и не принят».

## Резервный сценарий защиты

Остановите стенд с помощью `Ctrl+C` в его терминале и запустите из `ai`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -ForceFallback
```

В терминале запросов повторите:

```powershell
Invoke-AIDemo -Path '/api/ai/questions' -Payload $initial
Invoke-AIDemo -Path '/api/ai/card' -Payload $complete
```

Ожидается `X-AI-Mode: fallback` в обоих ответах. Questions содержат локальные вопросы на русском; определение уже закрытых категорий ограничено эвристиками. Card содержит ровно 11 строковых полей: `context` равен `Хотим автоматизировать работу склада` дословно, остальные поля пусты. Ответы не превращаются в полноценную карточку резервным кодом.

Реплика: «Резервный режим сохраняет исходное описание. Дальше человек заполняет карточку вручную; мы не подменяем AI заранее подготовленной карточкой». Можно открыть `testdata/cards.json` как **synthetic пример с источниками**, но нельзя показывать его как ответ текущего запроса. Если провайдер недоступен с начала выступления, сразу используйте этот сценарий и объясните основную ветку как подготовленный, но не проверенный live-путь.

Для возврата к обычной конфигурации остановите стенд и запустите ту же команду без `-ForceFallback`. В локальном `.env` должно быть `AI_FORCE_FALLBACK=false`. Фактический режим по-прежнему определяет заголовок ответа: отсутствие ключа или ошибка провайдера может снова привести к fallback.

## Использование fixtures и оценочных примеров

Все JSON-наборы в `testdata` имеют оболочку `{ "synthetic": true, "items": [...] }`. В `cards.json` идентификатор и `source` находятся вне `card`, поэтому контракт AI остаётся неизменным. `task_id` в proposals ссылается на `id` карточки, `team_id` — на `id` команды. Предложения сроков в proposals — синтетические предложения команды, а не обязательства бизнеса и не факты, добавленные AI.

В `evaluation_cases.json` записаны смысловые инварианты и запрещённые добавления для русских и казахских запросов, неизвестных сведений, противоречий, явных исправлений, prompt injection и других пограничных ситуаций. `forbidden_additions` означает запрещённый смысл или утверждение, а не наивный запрет слова: допустимо процитировать отрицание «интеграция с 1С не нужна». Оценивайте фактический live-ответ вручную и сохраняйте статус отдельно; фикстура и fake-provider тест не доказывают качество настоящей модели.

Известный конфликт: исчерпывающее описание может не оставлять трёх полезных уточнений. Минимум 3 вопроса по контракту не является основанием выдумывать проблемы или повторять уже известные факты. Этот случай отдельно включён в evaluation_cases и должен учитываться при обсуждении контракта с командой.
